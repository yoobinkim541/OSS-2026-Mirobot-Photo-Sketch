# 2026-09-30 — 기록에서 사용자 폴더 경로 지우기

## 문제

- 저장소는 공개(PUBLIC)인데, 실행 기록(`LOG/runs`)과 보정 기록(`LOG/calibrations`)에 컴퓨터 사용자 폴더 경로가 그대로 들어 있었다: 사진 경로(`C:/Users/<사용자>/Pictures/Saved Pictures/...`), 그림 좌표 파일·궤적 파일 경로, 설정 파일 경로. 사용자 이름과 개인 사진 폴더 이름, 실존 인물 사진 파일 이름이 드러났다.
- 찾은 곳: 실행 기록 5건, 보정 기록 3건, 옛 계획 문서 1건(WSL 명령의 `/mnt/c/Users/...`). 아직 커밋하지 않은 로컬 실행 기록 3건에도 있었다.

## 변경

- `paths.portable_path()` / `paths.scrub_paths()`: 절대 경로(드라이브 문자나 `/home`·`/Users`·`/mnt`·`/root`로 시작)를 **저장소 안이면 저장소 기준 상대 경로(`out/run_strokes_x.json`), 밖이면 파일 이름만(`IU.jfif`)**으로 바꾼다. 절대 경로가 아닌 값(`COM9`, `out/x.json` 등)은 그대로 둔다.
- 앞으로 저장되는 실행 기록(`write_run_record`)과 보정 기록(`calibration.save_report`)은 저장할 때 자동으로 경로를 정리한다.
- 이미 있는 기록 11건(추적 중 8건 + 로컬 3건)과 옛 계획 문서를 같은 규칙으로 정리했다(문서는 `/mnt/c/<사용자>/Desktop/Mirobot/`). 정리 뒤 저장소 안 LOG·문서에서 사용자 폴더 문자열은 남아 있지 않다.

## 확인

- 도우미 단위 테스트(저장소 안·밖, POSIX 경로, 경로가 아닌 값, 설치판 모드, 중첩 dict·list, 입력은 바뀌지 않음), 실행·보정 기록을 실제로 써서 사용자 폴더가 없는지, 저장소의 `LOG/runs`·`LOG/calibrations` JSON에 사용자 폴더가 없는지 검사하는 테스트를 추가했다.

## 알아 둘 점 (중요)

- **이미 GitHub에 올라간 옛 커밋의 내용은 그대로 남아 있다.** 파일을 고쳐도 커밋 이력에서 예전 경로를 볼 수 있다. 이력에서 지우려면 이력을 다시 쓰고(강제 push) 이미 만들어진 PR·포크에도 영향이 있어 하지 않았다. 필요하면 별도로 판단해야 한다.
- 새로 생긴 로컬 실행 기록 3건은 개인 사진 파일 이름(`IU.jfif`, `Waguri.webp`)이 파일 이름으로 남아 있어 커밋하지 않고 로컬에만 둔다.
- 사진 파일 이름 자체는 남는다(폴더만 지움).
