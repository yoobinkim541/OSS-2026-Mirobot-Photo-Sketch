# 사진 → 앱 → 로봇 좌표 전송 경로 확인 (2026-09-29)

## 앱 경로

1. `SketchSession`이 사진에서 획을 만들고 종이 중심 기준 mm 좌표로 변환한다.
2. `DrawJob`이 실행 시점의 획을 고정하고 허용 범위·관절 경로를 검사한다.
3. 실물 연결에서는 호밍과 필요한 종이 보정을 거친 뒤 사람이 최종 확인한다.
4. `draw_executor.execute`가 같은 획으로 만든 G-code를 한 줄씩 보내고 `ok`를 기다린다. 멈춤·오류 후 자동 복구는 하지 않는다.
5. 실제 전송에 쓴 좌표는 `out/run_strokes_*.json`, 결과는 `LOG/runs/run-*.json`에 기록한다.

- 389획, 명령 2,989개, 관절 시뮬레이션 PASS.

- 실행 기록: `LOG/runs/run-20260929-113130.json`. 좌표 파일: `out/run_strokes_20260929-113054.json`.

- 실행기 테스트 21개, 캘리브레이션 테스트 18개, 앱 작업 테스트 14개 통과. GUI 실행·종료 관련 표적 테스트 3개도 통과.

## 실물 상태

- 120 × 120 mm 외곽은 이전에 사람이 지켜보며 **공중 이동**으로만 확인했다.
- 기존 접촉 보정은 80 × 80 mm였고 그 뒤 종이·펜 위치를 조정했다. 설정을 `needs_recalibration`으로 표시했다.
- 작은 F 시험에서 아래쪽 펜촉이 걸렸다. 새 접촉 보정과 짧은 시험선의 선질 확인 전에는 사진 전체를 실물 펜다운으로 실행하지 않는다.
- 앱은 확장 영역 사진의 실물 실행 시 사진 외곽보다 1 mm 넓은 직사각형을 펜업으로 확인하고 네 모서리 접촉을 측정한다. 측정이 완료된 영역만 실물 펜다운을 허용한다.
- 이 직사각형 보정 경로는 가짜 로봇으로 검증했다. 실제 종이에서 120 mm 사진의 접촉과 선질은 아직 확인하지 않았다.
