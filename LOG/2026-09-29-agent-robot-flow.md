# 2026-09-29 — 앱 안 에이전트가 로봇으로 그리기까지 도울 수 있는지 확인·보강

## 확인한 것 (수정 전)

도구를 직접 호출해 확인했다(AI 모델과의 실제 대화는 API 키·창이 필요해 돌리지 못했고 도구 계층만 검증).

- 처리 설정(`set_params`), 획 보기·편집(`view`, `list_strokes`, `propose_edits` 등), 로봇 시뮬레이션(`simulate`)은 동작한다.
- 이미지 열기, 로봇 연결·호밍·시작·멈춤 도구는 없다(설계상 사람이 '로봇으로 그리기' 창에서 함). 그리는 동안은 읽기 도구만 허용(`drawing_lock`).
- 문제: (1) 지시문이 "내보내기 후 실행기에서 직접 시작"이라 현재 흐름(앱 창)과 달랐다. (2) 로봇 단계(호밍, 종이 세팅, 공중 모드, 넓은 범위, 다시 보정)와 오늘 겪은 막힘의 안내가 없었다. (3) 펜으로 그릴 수 있는 범위(세로 포함)를 알 방법이 부족했다(`executor_limit_mm`은 폭만). (4) 종이 보정 여부·그리는 중 여부가 상태에 없었다.

## 수정

- 새 읽기 전용 도구 `robot_guide`(`SketchSession.robot_guide()`): 펜으로 그릴 수 있는 영역·공중 확인 영역, 그림 크기·획·예상 시간, 시뮬레이션 결과, 종이 보정 여부, 문제(`issues`)와 주의(`notes`), 사람이 할 순서 4단계, "에이전트는 로봇을 못 움직인다" 문구. 판정: 시뮬레이션이 없거나 FAIL이거나 넓은 범위 밖이면 `ready: false`, 펜 그리기 범위 밖이면 `pen_down_possible: false`이고 공중 모드·크기 줄이기·다시 보정을 안내한다. 그리는 중에도 호출 가능.
- `get_state`에 `executor_limit_outline_mm`(펜 범위 윤곽), `plane_status`, `drawing`(그리는 중) 추가.
- 에이전트 지시문 개정: 펜 범위·공중 확인 범위 두 가지, 큰 그림이 아래로 배치되는 것, "로봇으로 그리기까지" 절차(simulate → robot_guide → 사람이 창에서), 공중 모드 먼저, 시작 자세=종이 중심 세팅, 그리는 중 읽기만 가능, 내보내기(JSON)는 명령줄 실행기용 별도 경로. 로봇을 움직이는 도구는 여전히 없다.
- 에이전트 패널: 추천 문구 "이 그림을 로봇으로 그릴 준비가 됐는지 확인하고 순서를 알려줘", 안내 문구를 "로봇 연결·시작은 사용자가 '로봇으로 그리기' 창에서 직접 합니다."로 수정. README 갱신.

## 확인 (실물·AI 대화 아님)

- 실제 사진(120 mm)으로: 시뮬레이션 전에는 "simulate 먼저" issue, 후에는 `ready`·`pen_down_possible` true와 "종이 보정 없음" 주의(현재 설정), 130 mm로 키우면 펜 범위 밖 점 15개와 공중 모드 안내.
- 테스트: 이미지 없음 안내, 시뮬레이션 전/후, 범위 밖이면 공중 모드 안내, 그리는 중 읽기 가능과 상태 필드, 지시문이 부르는 도구 이름이 실제로 있음. 에이전트·GUI 스모크 73개 통과.
- 미확인: 실제 AI 모델이 이 지시문과 도구를 보고 사용자를 제대로 안내하는지(대화 품질).
