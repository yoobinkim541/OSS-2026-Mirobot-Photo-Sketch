# 2026-09-29 — 로봇 시뮬레이션 중 앱이 멈추는 문제 수정

## 문제

- 증상: "로봇 시뮬레이션"을 누르면 시뮬레이션이 도는 동안 앱 창이 반응하지 않는다.
- 재현(실제 GUI를 띄우고 시뮬레이션 스레드가 도는 동안 화면 스레드가 20 ms마다 도는지 측정): 120 mm 그림(156획) 시뮬레이션 38.0초 동안 화면 갱신 이론상 약 1,900회 중 **33회**, 최대 **6.2초** 멈춤, 1초 넘는 멈춤 8번. 80 mm에서도 34.8초 중 47회, 최대 5.8초.
- 시뮬레이션은 이미 별도 스레드에서 돌고 있었다(`_sim_worker`). 원인은 스레드가 아니라 **GIL 경쟁**: 역기구학(IK)이 작은 numpy 연산을 수만 번 반복해 파이썬 스레드 전환이 기본 간격(5 ms)에서는 화면 스레드가 잠금을 거의 얻지 못한다.

## 시도한 방법 (80 mm 그림, 같은 측정)

| 방식 | 시뮬레이션 시간 | 화면 갱신 | 최대 멈춤 |
|---|---|---|---|
| 기본 | 34.8초 | 47 / 1,742 | 5.8초 |
| 스레드 전환 간격 0.5 ms | 36.6초 | 1,330 / 1,830 | 0.96초 |
| IK 20번마다 `sleep(1ms)` 양보 | 24.4초 | 134 / 1,222 | 0.97초 (Windows에서 sleep이 거칠어 갱신이 굼뜸) |

## 수정

- `gui.SketchApp.__init__`에서 `sys.setswitchinterval(0.0005)` (상수 `GIL_SWITCH_INTERVAL_S`). 시뮬레이션은 약 5% 느려지지만 창이 끊기지 않는다. 시뮬레이션 코드(`mirobot_sim`)와 결과는 그대로다.
- 로봇으로 그리기 창의 사전 검사(①)도 같은 시뮬레이션을 작업 스레드에서 돌리므로 같은 효과를 받는다.

## 확인

- 테스트 2개 추가(`GuiResponsivenessTest`): 시뮬레이션이 스레드에서 도는 동안 화면 스레드의 최대 멈춤이 1초 미만, 앱이 전환 간격을 0.5 ms 이하로 줄임. **수정을 끄면 두 테스트가 실패**(화면이 7.5초 멈춤, 갱신 33회)하고 수정하면 통과함을 확인.
- 실제 앱 창을 사람이 눌러 본 확인은 하지 않았다. 측정은 같은 앱을 띄운 자동 실행이다.
- 남은 개선 후보: IK가 느린 것 자체(120 mm에서 약 38초). 유한 차분 야코비안 대신 해석적 계산이나 캐시로 줄일 수 있다.
