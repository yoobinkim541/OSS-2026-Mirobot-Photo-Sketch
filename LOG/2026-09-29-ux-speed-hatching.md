# 2026-09-29 — UX·속도 개선과 명암 빗금 (전체 검사 후속)

전체 검사(문구·시간·에이전트·사진 닮음)에서 나온 항목을 모두 진행했다. 측정은 이 컴퓨터, 같은 샘플 사진, 실제 앱을 띄워서 했다.

## ① 로봇 시뮬레이션 속도

- 문제: 시뮬레이션이 20~96초. "로봇으로 그리기"는 펜 경로와 공중 경로를 각각 한 번씩(총 2번) 돌려 호밍 전에 1~3분 기다릴 수 있었다.
- IK를 알고리즘은 그대로 두고 배치로 계산(`fk_batch`: 관절 축이 모두 z축이라 회전을 직접 계산, 유한 차분 야코비안의 7개 자세를 한 번에). 직선 구간은 앞선 두 점으로 다음 자세를 예측해 시작해 반복을 줄임.
- 기준 저장 후 비교: 마이크 58.8초 → 약 18초, 일러스트 62.8초 → 약 18초(3.2~3.6배). 관절각 차이 최대 1e-5 rad, 최소 여유 차이 2e-7°, 실패·위반 개수 동일. 작은 함수 호출이 많은 구조라 더 줄이려면 해석적 야코비안이나 분할 계산이 필요(미착수).
- 공중 경로 시뮬레이션은 사람이 ④ 최종 확인을 하는 동안 백그라운드로 돌리고, 공중 모드를 골랐을 때만 기다림(펜 모드는 안 기다림). 작업이 끝나거나 취소되면 남은 계산도 멈춘다(`SimulationCancelled`).
- 시뮬레이션 버튼은 진행률(퍼센트 + 막대)을 보여 준다.

## ② 문구·레이아웃

- "먼저 '처리 실행'을 해주세요"(없는 버튼) → "먼저 이미지를 열어 주세요".
- 그림 크기 카드의 "실행 시 --pending-limits 필요" / "실행기 허용 범위" → "공중 확인 범위도 넘음: 크기를 줄이세요" / "펜 범위 밖: 공중 모드로 확인" / "펜으로 그릴 수 있는 범위 안".
- JSON 내보내기 완료창: 옛 `python robot/draw_executor.py` → "앱에서 바로 그리려면 '로봇으로 그리기', 명령줄은 mirobot-draw".
- 종이 미리보기 안내를 "펜으로 그릴 수 있는 범위 / 공중 모드로만 확인하는 넓은 범위"로 쉽게.
- RViz 버튼 3개는 "고급: RViz 3D ▸" 접이식으로. 조절 항목 이름을 쉬운 말로(Canny 하한 → 약한 선 민감도 (Canny 하한) 등). 로봇으로 그리기 창의 배속 메뉴는 가상 시뮬레이션일 때만 보임.

## ③ 화면 렌더링

- 단계 전환이 조절 패널을 통째로 파괴·재생성(0.2~0.34초)하던 것을 단계별로 한 번만 만들고 재사용. 결과를 보여줄 때 편집 그림을 두 번 그리던 것을 한 번으로. 앱을 닫을 때 Tk 객체를 메인 스레드에서 정리(`gc.collect`).
- 측정(마이크 사진, 367획): 단계 전환 평균 약 1.0초 → 0.47초(두 번째 순회부터; 처음 여는 단계는 조절 칸을 만드느라 약 0.9초). 결과 표시(`_show_result`) 0.8~1.0초, 슬라이더 변경 후 갱신 1.3~2.1초는 matplotlib 그리기가 대부분이라 큰 변화 없음(남은 과제).
- 테스트 중 발견: 조절 패널을 다시 만들 때 하던 `gc.collect()`를 없애자, 앞선 테스트가 닫은 창의 Tk 글꼴 객체를 다음 테스트의 작업 스레드가 정리하려다 영원히 기다려 테스트가 멈췄다. 닫을 때 메인 스레드에서 정리하도록 고쳐 해결.

## ④ 에이전트 편의

- 기본 연결 방식: 저장한 선택이 쓸 수 있으면 그대로, 아니면 설치된 것/키가 있는 것 중 첫 번째(Claude Code → Codex → OpenRouter). 설정 파일은 바꾸지 않음.
- 첫 응답 전 "생각하는 중… N초", 긴 도구 칩에 경과 시간과 simulate "(그림에 따라 10~30초)". 새 대화에서 정리.
- 에이전트가 작업하는 동안 화면에 "설정·시뮬레이션이 잠깁니다. 끝나면 자동으로 풀려요." 표시. 빈 화면 안내에 로봇 준비 확인 예시 추가.

## ⑤ 사진과 닮고 예쁘게: 명암 빗금 + 비교 도구

- 출력 그림을 원본과 비교하니 지금은 윤곽만 있어 어두운 머리·옷이 비어 인상이 다르고, 어두운 배경 사진은 빛망울이 동그라미로 그려졌다.
- 새 단계 "명암 빗금"(`tone`, 기본 꺼짐): 어두운 면을 평행 빗금(2단계부터 교차)으로 채우고 이어지는 줄은 지그재그로 이어 펜 올림을 줄인다. 조절: 단계, 간격(mm), 방향, 짧은 빗금 버리기, 어두움 기준. 빗금은 편집 번호표에 넣지 않고(번호가 수백 개로 불어남) 그리기 순서를 정할 때 윤곽과 합쳐 종이 배치·시간·시뮬레이션에 포함. 배경이 어두운 사진은 빗금이 화면을 덮어 만들지 않고 "배경 제거를 켜 보세요"로 안내.
- 새 읽기 전용 도구 `compare`: 원본 | 그림 | 차이(빨강 = 사진보다 밝게, 파랑 = 어둡게) 그림과 지표(tone_match 명암 닮음, edge_recall 윤곽 재현, edge_precision 잡음(윤곽 획만 계산), under/over_shaded_pct, ink_coverage_pct)와 개선 hints. 에이전트 지시문에 "compare → 설정 변경 → 다시 compare(2~3회) → 눈으로 확인" 절차와 순서(배경 제거 → 프리셋 → 정리 → 명암 → 시간 점검)를 추가.
- 측정(마이크 사진, 배경 제거, 100 mm, 보통 상세도):

| 명암 단계 | 명암 닮음 | 사진보다 밝게 그려진 면적 | 윤곽 재현 | 획 | 예상 시간 |
|---|---|---|---|---|---|
| 0 (꺼짐) | 0.71 | 31.8% | 0.94 | 250 | 17.8분 |
| 1 | 0.88 | 12.3% | 0.96 | 275 | 25.1분 |
| 2 | 0.93 | 0.0% | 0.97 | 286 | 31.2분 |
| 3 | 0.94 | 0.0% | 0.98 | 314 | 38.6분 |

- 눈으로 본 결과: 2단계에서 모자·머리카락·장갑·스웨터가 빗금으로 채워져 판화 같은 초상이 되고 얼굴은 밝게 남는다. **닮음·예쁨은 사람의 판단**이므로 지표는 보조이고, 실제 종이에 그렸을 때의 느낌은 확인하지 못했다(펜 굵기·종이 접촉에 따라 달라짐).
- 시간 대가가 크다(2단계 +13분). 그래서 기본은 꺼짐이고, 사용자가 "닮게/예쁘게"를 원하거나 시간 여유가 있을 때 에이전트가 제안한다.

## 테스트

- 추가: 고속 FK·IK가 예전 구현과 같은 결과, 확장 시작·진행률·취소, 공중 경로 백그라운드(대기 여부·취소), 화면 문구·접이식·배속 메뉴, 에이전트 패널 UX(생각 중, 경과 시간, 기본 연결 방식), 명암 빗금(어두운 면에만, 단계·간격·기준 효과, 지그재그 묶기, 어두운 배경 거부, 결정성), 사진-그림 비교(지표, 윤곽 정밀도가 빗금에 영향받지 않음), tone 단계·세션 연동(번호표 불변, 배치·시간 반영, 편집·되돌리기 후 유지), `compare` 도구.
- 미확인: 실제 AI 모델이 새 지시문·도구로 잘 동작하는지, 빗금 그림을 실제 로봇으로 그렸을 때의 선질과 시간, 사람 눈으로 본 "예쁨".
