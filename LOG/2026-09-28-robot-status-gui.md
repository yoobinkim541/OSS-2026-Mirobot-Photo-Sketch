# 2026-09-28 — GUI 로봇 USB·컨트롤러 상태 표시

## 목표

GUI 상단에서 로봇의 USB 연결과 실제 컨트롤러 상태를 구분해 보여 준다. USB 상태 확인이 시리얼 포트를 새로 열어 보드를 리셋하지 않도록 한다.

## 구현

- 헤더에 `USB: COM9 감지/미감지`와 `제어기 상태: ...`를 따로 표시한다.
- 3초 간격으로 `serial.tools.list_ports.comports()`를 백그라운드에서 호출해 설정된 COM 포트가 운영체제에 나타나는지 확인한다. 시리얼 포트를 열거나 명령을 보내지 않는다.
- 실제 그리기 작업은 이미 연 `MirobotLink` 연결에서 호밍 중 `Alarm`/`Idle` 상태를 전달하고, 실행 중 `그리는 중`을 표시한다. 정상 완료 시 최근 상태를 `Idle`로 기록한다. 드로잉 중 중단하면 모터 상태를 추측하지 않고 미확인으로 표시한다.
- 가상 실행의 상태를 실물 컨트롤러 상태로 표시하지 않는다.
- README와 LOG 색인을 갱신했다.

## 검증

- 새 상태 로직 테스트 7개 통과: COM 포트 일치(대소문자·접두어), 누락 설정, 상태 문구 추출, 연결/호밍/드로잉/완료 이벤트.
- 기존 로봇 실행기 테스트 20개 통과.
- 변경 Python 파일은 `compile()` 문법 검사 통과, `git diff --check` 통과.
- 전체 테스트는 126개를 발견했으며 14개 import 오류와 1개 skip으로 끝났다. 제공된 Codex Python 런타임에 OpenCV `cv2`가 없어 에이전트, 드로잉 작업, GUI 및 CV 테스트를 불러오지 못했다. 따라서 전체 테스트와 GUI 스모크 검증은 이 환경에서 완료하지 못했다.
- Windows의 읽기 전용 COM 열거에서는 COM9가 보였다. 이 작업 중 시리얼 포트를 열거나 로봇에 동작 명령을 보내지는 않았다.

## 남은 확인

프로젝트 의존성이 설치된 Windows Python에서 GUI를 열어 COM9 USB 표시를 확인하고, 실제 연결·호밍 과정의 `Alarm → Idle` 표시를 검증한다. USB 감지는 컨트롤러 응답이나 모터 구동 준비 완료를 뜻하지 않는다.
