## 설치

| | Windows 10/11 | 로봇 | RViz 3D (선택) |
|---|---|---|---|
| 필요한 것 | 64비트 Windows (.exe 설치는 파이썬 불필요) | WLKATA Mirobot + USB(CH340) 케이블, A4 용지, 펜 | Windows 11 + WSL2 (또는 Ubuntu 22.04) |

로봇 없이도 선 추출·시뮬레이션·가상 시뮬레이션은 모두 됩니다. RViz 3D는 없어도 됩니다.

### 방법 1. 설치 프로그램 (.exe, 추천)

[Releases](https://github.com/yoobinkim541/OSS-2026-Mirobot-Photo-Sketch/releases)에서 `MirobotSketch-Setup-X.Y.Z.exe`를 받아 실행합니다.

- 시작 메뉴와 바탕화면(선택)에 **Mirobot Sketch** 바로가기가 생기고 "앱 및 기능"에서 제거할 수 있습니다. 관리자 권한은 필요 없습니다.
- 설치 중 **"RViz 3D 환경도 설치"** 를 체크하면 설치 후 3D 환경 설치 도우미가 열립니다(약 400MB 다운로드).
- 코드 서명이 없어 처음 실행할 때 Windows SmartScreen이 "알 수 없는 게시자" 경고를 띄울 수 있습니다. **추가 정보 → 실행**을 누르면 됩니다.

설정 파일은 처음 실행할 때 `%APPDATA%\MirobotSketch\drawing_config.json`에 만들어지고, 실행 기록은 같은 폴더의 `runs\`에 쌓입니다. 이 파일에서 보정값을 고칩니다. 로봇 포트는 기본값 `"port": "auto"`로 자동으로 찾으므로 보통 고칠 필요가 없습니다. 배경 제거(rembg)는 용량 문제로 .exe에 넣지 않았습니다.

### 방법 2. zip (설치 없이)

같은 릴리스의 `MirobotSketch-vX.Y.Z-windows-x64.zip`을 풀어 `MirobotSketch.exe`(GUI)나 `mirobot.exe`(명령줄: `mirobot draw …`, `mirobot strokes …`, `mirobot sim …`, `mirobot setup-rviz …`)를 실행합니다.

### 방법 3. 개발자 설치 (파이썬 3.10 이상)

```bash
git clone https://github.com/yoobinkim541/OSS-2026-Mirobot-Photo-Sketch.git
cd OSS-2026-Mirobot-Photo-Sketch
pip install -e .
```

`mirobot-sketch`(GUI), `mirobot-strokes`, `mirobot-svg`, `mirobot-draw`, `mirobot-sim` 명령이 생깁니다. 저장소에서 실행하면 `robot/drawing_config.json`, `LOG/runs/`, `out/`을 그대로 씁니다. 필요한 기능만 추가로 설치합니다.

| 추가 기능 | 명령 |
|---|---|
| 배경 제거 (첫 실행 때 모델 약 170MB 다운로드) | `pip install -e ".[rembg]"` |
| 에이전트 패널 (MCP, keyring, requests) | `pip install -e ".[agent]"` |
| .exe 빌드 | `pip install -e ".[build]"` 후 `pyinstaller packaging/mirobot_sketch.spec --noconfirm` |

저장소 코드를 바로가기로 실행하려면 한 번만 실행합니다(바탕화면과 시작 메뉴에 생김, 콘솔 창 없음, `-Remove`로 삭제).

```bash
powershell -ExecutionPolicy Bypass -File packaging/create_shortcuts.ps1
```

### RViz 3D 환경 설치 (선택: WSL2 + ROS 2 Humble + Mirobot 모델)

3D 보기와 실시간 따라가기에만 필요합니다. 아래 중 편한 방법 하나를 고르세요.

**A. 설치 도우미 (추천, 버튼 한 번)** — 미리 만든 이미지(약 400MB, 설치 후 약 2GB)를 받아 `MirobotSketch-ROS` 배포판으로 가져옵니다(약 2분 + 다운로드). 기존 WSL 배포판은 건드리지 않습니다.

- **GUI:** 왼쪽 아래 "03 검증 및 드로잉"의 `고급` → [RViz 3D 환경 설치·확인…] → [설치]. 끊겨도 [이어서 설치]로 받던 곳부터 이어받습니다.
- **명령줄:** `mirobot setup-rviz --check | --install | --uninstall | --manual | --wsl`
- **설치 프로그램:** "RViz 3D 환경도 설치" 체크. 앱을 지울 때 배포판도 지울지 묻습니다.
- **WSL이 없는 PC:** [WSL 설치(관리자)] → Windows 승인 → 재부팅 → [설치]. 관리자 권한은 이 한 번뿐이고 비밀번호는 받지 않습니다.

**B. 셸 스크립트로 직접 설치** — Ubuntu 22.04(WSL2 또는 리눅스)의 터미널에서 실행합니다.

```bash
git clone https://github.com/yoobinkim541/OSS-2026-Mirobot-Photo-Sketch.git
cd OSS-2026-Mirobot-Photo-Sketch
bash packaging/wsl/setup_ros_env.sh
```

ROS 2 Humble(`ros-base`, `rviz2`, `robot_state_publisher`)과 WLKATA 모델(`~/mirobot_ws`)을 설치하고, 이미 끝난 단계는 건너뛰며, 마지막 줄에 `SETUP_OK`를 출력합니다. 필요한 곳에서만 `sudo` 비밀번호를 묻습니다. Ubuntu 22.04(jammy)가 아니면 종료합니다. 앱은 `/opt/ros/humble`과 `~/mirobot_ws`가 있는 WSL 배포판을 자동으로 찾고, 다른 배포판을 쓰려면 환경 변수 `MIROBOT_WSL_DISTRO`를 지정합니다.

**C. 설치 도우미의 예비 경로** — 이미지를 받을 수 없을 때 [직접 설치(예비)]: Ubuntu 공식 22.04 WSL 루트 파일(약 230MB, SHA256 확인)을 받아 전용 배포판 `MirobotSketch-ROS`로 가져온 뒤 그 안에서 `setup_ros_env.sh --image`를 실행합니다. 사용자의 기존 배포판은 건드리지 않고, 비밀번호·추가 관리자 승인이 없습니다.

손으로 재생하려면 궤적을 내보낸 뒤 WSL2에서 실행합니다.

```bash
mirobot-sim out/photo.json --export out/photo_traj.json
wsl -d MirobotSketch-ROS -- bash -lc "cd /mnt/c/<저장소 경로> && bash sim/run_rviz.sh out/photo_traj.json 10"
```

## 사용법

### 1. 사진 → 획 JSON

GUI (추천):

```bash
mirobot-sketch            # 또는 python CV/gui_sketch.py
```

CustomTkinter 기반의 스튜디오형 화면으로, 라이트/다크 모드에 같은 색상·버튼·카드 규칙을 적용합니다. 처음에는 중앙의 **이미지 열기**로 시작하고, 왼쪽 "01 사진과 추천 설정"에서 이미지 종류(실사 사진 / 컬러 일러스트 / 흑백 만화)와 선의 상세도를 고르면 추천 설정이 들어갑니다. 그 아래 "02 단계 조절"은 따로 스크롤되며 **"03 검증 및 드로잉" 버튼은 왼쪽 아래에 고정**됩니다. 진행 막대와 지금 하는 일은 맨 아래 상태 줄에 표시합니다. A4 종이 위에 실제 크기와 펜 굵기로 미리 보여 주고, 예상 시간(그리기·이동·펜 올림/내림·명령 지연)과 로봇 시뮬레이션(관절 한계 PASS/FAIL) 결과를 요약 카드로 함께 표시합니다.

- **화면 크기:** Windows 화면 배율(DPI)과 작업 표시줄을 뺀 실제 화면 크기로 창을 열고, 노트북처럼 좁은 화면(DPI 반영 1800 미만)에서는 최대화로 시작합니다. 글자·버튼·여백은 창 크기를 따라 커지고 작아집니다(1280×800에서 100%, 80%~160%). 머리글의 **화면 크기 [−] [+]**(Ctrl+- / Ctrl+= / Ctrl+0)로 더 키우거나 줄일 수 있고, 고른 값은 다음 실행에도 쓰입니다(`%APPDATA%\MirobotSketch\ui.json`). 오른쪽 작업 영역이 넓으면 요약 카드를 큰 보기 옆에 세로로, 좁으면(에이전트 패널을 연 경우 등) 아래에 가로로 놓습니다.
- **단계 띠:** 원본 → 전처리 → 선 검출 → 뼈대·획 → 겹침 제거 → 이어 붙이기 → 얼굴 세밀 → 잔선 정리 → 스무딩·단순화 → 명암 빗금 → 편집 → 순서·종이. 단계를 누르면 큰 보기와 왼쪽 조절 칸이 그 단계로 바뀌고, 조절 칸이 가려져 있으면 왼쪽 목록을 굴려 보여 줍니다. 띠가 넓으면 버튼이 폭을 나눠 채우고, 좁으면 마우스 휠로 좌우로 넘기며, 선택한 단계가 가려져 있으면 자동으로 이동합니다. **← 이전 단계 / 다음 단계 →** 버튼이나 ←/→ 키로도 이동합니다.
- **실사 인물:** 선 검출 전에 사진을 Informative Drawings 선화로 바꾸고, 그 선화를 그대로 따라 그립니다. 진한 선과 거기 이어진 옅은 끝부분을 따고, 눈동자처럼 두꺼운 먹 덩어리는 테두리로, 점선처럼 끊긴 선은 방향이 맞으면 이어서 그리며, 이어도 짧은 토막(작업 이미지 6px, 펜 굵기의 1.5배 미만)은 뺍니다. 선화는 이미 한 줄짜리 선이라 Canny용 "굵은 선 양쪽 경계 지우기"는 하지 않습니다(하면 머리카락·눈꺼풀·입술처럼 가까운 선이 쌍으로 사라짐). 얼굴은 원본 해상도로 자른 조각에 선화 모델을 한 번 더 돌려 눈·코·입을 다시 그립니다. 선 선별 결과는 아래와 같습니다.
  - **남기는 선:** 사람이 보고 닮았다고 느끼는 선을 남깁니다. 눈·눈썹·코·입, 얼굴 윤곽, 머리 모양, 로고·문양입니다. 사진 속 글자는 기본으로 지웁니다(아래).
  - **지우는 선:** "잔선 정리" 단계(기본 켬)가 아래 선들을 지웁니다. 강도는 "얼굴 밖 짧은 선 기준(mm)"과 "흐린 선 기준(백분위)"으로 정하고, "선 개수 상한"을 두면 얼굴 밖에서 덜 중요한(짧고 흐린) 선부터 뺍니다. 얼굴 안, 얼굴 둘레(턱선·머리선·귀), 배경을 지운 인물 외곽선은 강도를 올려도 기본 기준으로 보고 상한에서도 지킵니다. 머리카락 결을 켜면(실사 프리셋) 머리 영역 안의 선화 획은 사진 대비가 약해도 실제 머리 결이라 짧은 토막(종이 2mm(펜 굵기의 4배)와 "얼굴 밖 짧은 선 기준"의 1/3 중 긴 쪽보다 짧은 것)만 빼고 남깁니다. 상한에서는 다른 선을 모두 뺀 뒤에도 넘을 때만 짧은 결부터 뺍니다(끝까지 지키면 긴 생머리 사진이 가장 강하게 정리해도 45분을 넘었음).
    - 피부 위 주름: 볼·이마처럼 선 양옆이 모두 피부색인 짧은 선입니다. 피부색은 그 사진의 양 볼과 코 옆에서 잽니다.
    - 짧고 흐린 잔선: 얼굴 밖에서 종이 3mm보다 짧고 사진 대비가 낮은 선입니다. 문양과 (아래 "사진 속 글자 지우기"를 끈 경우) 글자는 짧아도 대비가 커서 남습니다. 단, 선 개수 상한(자동 세팅이 시간을 맞출 때 씀)을 쓰면 짧은 글자 획부터 빠질 수 있습니다.
    - 이 사이 경계와 얼굴 속 점: 종이 위 얼굴은 수 cm라 이 하나하나의 경계나 1mm 남짓한 토막(눈꼬리·콧구멍 둘레)을 0.5mm 펜으로 그리면 덩어리·점이 됩니다. 얼굴 안에서 종이 1.25mm보다 짧은 토막은 뺍니다. 정면 얼굴의 입은 입꼬리를 지나는 매끄러운 윤곽(웃으며 벌린 입은 닫힌 곡선, 다문 입은 한 줄)으로 다시 그리고, 벌린 입 안에는 이의 아래 끝을 한 줄로 넣어 이가 보이는 웃음을 남깁니다. 옆얼굴·돌린 얼굴은 입을 그대로 둡니다.
    - 눈·눈썹·다문 입 다시 그리기와 턱선 잇기(기본 켬): 얼굴 점 478개로 정면 얼굴의 눈 속 선(안경 반사광·속눈썹 토막)을 지우고 윗눈꺼풀 곡선, 아래 눈꺼풀(눈꼬리~가운데 너머), 눈꺼풀 안쪽만 남긴 홍채 원과 펜 굵기 점 하나(눈동자)로 그립니다. 감은 눈은 윗눈꺼풀만 그립니다. 눈썹은 끊긴 조각 대신 위·아래 윤곽 사이 가운데 한 줄(두꺼우면 두 줄)로 그립니다. 다문 입은 입술 사이 선(입꼬리~입꼬리)과 윗·아랫입술 바깥선의 가운데 부분으로 그립니다. 바깥선을 입꼬리까지 이으면 벌린 입처럼 보였기 때문입니다. 턱선은 선화가 놓친 구간 중 사진에 경계가 보이는 곳만 얼굴 점 곡선으로 채웁니다. 코는 얼굴 점으로 그려 보니 둘째 입처럼 보여 선화 그대로 둡니다. 벌린 입은 위의 입 정리를 그대로 쓰고, 두 눈 폭 비가 0.6 미만인 돌아간 얼굴은 다시 그리지 않습니다. 얼굴 점 모델은 MediaPipe Face Landmarker의 모델을 ONNX로 바꾼 것(4.9 MB)으로, 선화 모델처럼 처음 쓸 때 GitHub Releases에서 내려받아 onnxruntime으로 돌립니다. 못 받으면 예전처럼 그리고 상태 줄에 이유를 표시합니다.
    - 사진 속 글자(기본 켬): 화보 제목·이름 자막·옷의 로고 글자는 0.5mm 펜으로 그리면 뭉개져 읽히지 않으므로, 글자 검출 모델(PP-OCRv3, OpenCV Zoo, 2.4 MB, 처음 쓸 때 내려받음)이 찾은 영역의 선을 지웁니다. 얼굴 안에서 찾은 글자는 오검출로 보고 둡니다. 옷의 로고 글자(예: 초상의 NASA 패치)도 지워지므로, 남기려면 "사진 속 글자 지우기"를 끕니다.
    - 지운 선은 편집 단계의 "버린 선"에 이유와 함께 보입니다.
  - **효과와 시간:** 사진 4장에서 선화가 그린 선 중 최종 획에 남는 비율이 0.28~0.34 → 0.71~0.77로 올랐습니다(잔선 정리 전 기준). 대신 그리는 시간이 늘었습니다. 저장된 자세로 그릴 때(펜 20mm 올림) 초상 기준 약 21분 → 53분입니다(잔선 정리 없이는 74분). 시간 카드는 실제로 그릴 좌표와 펜 올림 높이로 계산합니다.
  - **모델 내려받기:** 선화 모델(17 MB)은 저장소에 없고 처음 쓸 때 GitHub Releases에서 내려받습니다. 내려받을 수 없으면(오프라인 등) 기본 선 검출로 그리고 그 이유를 상태 줄에 표시합니다. 일러스트·만화는 기존 방식을 유지합니다. 모델 출처와 라이선스는 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)에 있습니다.
- **자동 세팅(목표 45분):** "01 사진과 추천 설정"의 [자동 세팅]을 누르면 사진마다 잔선 정리 강도 후보를 실제로 계산해 보고, 예상 시간이 45분 안에 드는 후보 중 "닮음 점수"가 가장 높은 설정을 적용합니다. 스케치는 채색 전 첫 단계라 면을 빗금으로 메우지 않으므로 빗금은 후보에 넣지 않고(필요하면 "명암 단계"를 직접 올림), 머리카락은 결 선으로 그립니다. 강도만으로 시간을 못 맞추면 선 개수 상한을 이분 탐색합니다. 그래도 못 맞추면(긴 생머리처럼 머리 결 획이 많은 사진) 머리 결 간격을 3mm, 4mm로 넓혀 상한을 다시 찾고, 마지막에만 결 선을 끕니다. 결과 줄에 "결 간격 4mm(시간)"이나 "머리 결 선 끔(시간)"을 붙입니다. 점수는 눈·코·입·얼굴 윤곽 재현(0.40), 인물 외곽선(0.15), 사진 윤곽 재현(0.15), 명암 닮음(0.15), 잡음 없는 정도(0.15)를 더한 값입니다. 사진 한 장에 10~60초 걸리고, 그동안 조절 칸·사진 열기·그리기가 잠깁니다. 얼굴을 찾았는데 이미지 종류가 실사 사진이 아니면 실사 사진 프리셋으로 바꾼 뒤 찾고, 도중에 실패하면 원래 설정으로 되돌립니다. 여러 장은 명령줄로 돌립니다: `python -m mirobot_sketch.autotune 사진1 사진2 --target 45 --out out/auto`(원본|획 나란히 보기, 종이 미리보기, 보고 JSON, `mirobot-draw`로 바로 그릴 수 있는 획 파일 `<이름>_strokes.json` 저장. 같은 이름으로 다른 사진의 결과가 이미 있거나 한 번에 겹치면(`a.webp`·`a.jfif`) `a_jfif`처럼 확장자를 붙여 덮어쓰지 않음).
- **자동 재계산:** 값을 바꾸고 0.3초 뒤, 바뀐 단계부터만 다시 계산합니다(뒤 단계만 바꾸면 0.01초 안팎). 숫자 칸에서 ↑/↓ 키를 누르면 한 칸씩 바뀝니다.
- **가까운 획 이어 그리기(기본 1mm):** 앞 획 끝에서 "가까운 획 이어 그리기" 거리 안에 다음 획이 시작하면 펜을 들지 않고 짧은 직선으로 이어 그립니다. 저장된 자세(펜 20mm 올림)로 그리면 획마다 올림·내림이 약 5초라 시간의 대부분이 여기서 나오기 때문입니다. 1mm(펜 굵기 2배)로 사진 3장이 2.7~7.8분 줄었습니다. 얼굴 상자 안(눈썹~턱)은 잇지 않습니다: 얼굴을 4배로 키워 실제 펜 굵기로 보니 이음선이 눈 밑·눈꺼풀 위에 삐친 자국으로 남았습니다. 얼굴 안을 빼면 사진마다 1.0~1.9분 덜 줄어듭니다. 이음선이 종이에서 보이는지는 아직 실물로 확인하지 않았습니다. 0으로 두면 끕니다.
- **머리카락 결(실사 사진 프리셋은 켬):** 머리카락을 빗금으로 메우지 않고, 사진의 결 방향을 따라 고르게 띄운 흐름선을 긋습니다(기본 간격 2mm). 선화가 이미 그린 머리 결은 그대로 두고, 결 선은 그 사이 빈 곳만 채웁니다. 결 방향은 경계 접선 흐름(ETF, Kang 2007)으로 정합니다. 밝기 기울기에 수직인 접선을 주변의 뚜렷한 결 방향으로 되풀이해 다듬는 방식이라, 이전의 구조 텐서처럼 짧은 머리에서 결이 머리 윤곽을 따라 동심원으로 돌지 않고 정수리에서 앞머리로 흘러내립니다. 머리 영역은 얼굴 위·옆에 걸친 어두운 덩어리를 머리 둘레(얼굴 상자 위로 1배·양옆 0.8배, 턱 바로 밑까지)로 자른 곳이라, 머리와 이어진 어두운 옷에는 긋지 않습니다. 결 선은 빗금처럼 편집 번호에 들어가지 않고 그리기 순서를 정할 때 윤곽과 합쳐집니다.
- **명암 빗금(기본 꺼짐):** 면에 명암을 넣고 싶을 때 "명암 단계"를 1~3으로 올리면 어두운 면을 평행 빗금으로 채우고, 더 어두운 곳은 같은 방향 줄 사이에 줄을 더 넣어 촘촘하게 합니다. 예전에는 2단계부터 방향을 90° 돌린 교차 빗금이었는데, 0.5mm 펜으로 그리면 머리카락이 바구니 같은 격자로 보여 바꿨습니다. 이어지는 빗금은 펜을 떼지 않고 지그재그로 이어 펜 올림을 줄입니다. 빗금은 선화가 아니라 사진의 밝기로 정합니다. 배경이 어두운 사진은 먼저 "배경 제거"를 켜야 하며 안 켜면 빗금을 만들지 않고 안내합니다. 교차 빗금 시절 마이크 사진(배경 제거) 기준으로 명암 닮음이 0.71 → 0.88(1단계) → 0.93(2단계)로 올랐고, 예상 시간도 17.8 → 25.1 → 31.2분으로 늘었습니다. "얼굴 피부에는 빗금 안 함"(기본 켬)은 눈썹 아래 얼굴과 목·귀의 피부에 빗금을 긋지 않습니다. 종이 위 얼굴은 수 cm라 피부 그림자 빗금이 흉터·수염처럼 보여 표정을 가리기 때문입니다. 결 선을 그린 머리에도 빗금을 넣지 않습니다.
- **선 검출 방식:** 밝기(흑백 Canny) / 색 차이(Lab Canny, 밝기가 비슷한 색의 경계도 찾음) / 어두운 선(선화 중심선).
- **얼굴:** 실사 사진은 OpenCV YuNet으로 얼굴을 찾습니다([모델 라이선스](../THIRD_PARTY_NOTICES.md)).
  - **자동 구도:** 전신 사진처럼 종이 위 얼굴이 25mm보다 작으면 원본 해상도에서 상반신으로 잘라 그립니다. "구도"에서 전체·상반신·얼굴을 직접 고를 수도 있습니다.
  - **얼굴 세밀:** 얼굴 부분만 원본 해상도로 다시 선을 찾고(실사 선화 경로도 같음), 펜 굵기보다 촘촘한 선은 합쳐 종이에서 뭉개지지 않게 합니다. 눈·코·입 근처의 짧은 선은 살립니다.
- **큰 보기:** 휠 또는 [+]/[−]로 확대·축소, 끌어서 이동, 더블클릭 또는 **화면에 맞춤** 버튼으로 전체 보기. 그림 바로 아래의 **이전 단계와 비교**를 누르고 있는 동안 앞 단계 결과를 보여 주고, "원본 겹치기"로 컬러 원본을 비치게 해 빠진 선을 찾습니다. 순서·종이 단계에서는 가이드 선(파랑: 펜 범위, 주황: 공중 확인 범위) 설명을 그림 위에 표시합니다. 이미지·비교 대상이 없는 기능은 비활성화됩니다.
- **편집 단계:** 획마다 번호가 붙습니다(확대한 범위에서 보이는 획만). "버린 선"을 켜면 파이프라인이 버린 조각이 회색 점선과 번호로 보입니다. 에이전트가 제안한 편집은 빨강(사라짐)·초록(생김)으로 표시되고, 아래 제안 바에서 번호 딱지를 눌러 뺀 뒤 [적용]합니다. 적용한 편집은 설정을 바꿔 다시 계산해도 유지됩니다.

#### 그리기 창과 카메라

- **로봇으로 그리기:** 왼쪽 아래 "03 검증 및 드로잉"의 [로봇으로 그리기] 창에서 ①사전 검사 → ②연결·호밍 → ③시작 위치 확인 → ④최종 확인 → ⑤그리는 중 → ⑥끝 순서로 진행합니다. 진행 중인 단계와 지금 할 일, 멈춘 이유가 단계 표시줄에 보입니다. 그림이 끝까지 그려지면 펜을 **처음 위치**(종이 중심, 펜 끝이 종이에 살짝 닿은 시작 자세)로 되돌리고(옵션, 기본 켬; 공중 모드는 해당 없음), 이어서 사진과 작업 내용(획·편집 기록·시뮬레이션)을 비워 새 그림을 바로 시작할 수 있게 합니다(옵션, 기본 켬; 이미지 종류·상세도·크기 같은 설정은 그대로 둠). 되돌리는 중 오류가 나면 그대로 알려 줍니다. 되돌리기는 그림 명령이 모두 끝난 뒤 별도로 보내므로 시뮬레이션·RViz 진행 표시와 어긋나지 않습니다.
  - **멈춤과 이어 그리기:** 그리는 중에 [■ 멈춤]을 누르면 작업이 끝나지 않고 **일시정지**합니다. 보내던 명령이 끝나면 그 자리에서 펜을 종이 반대쪽으로 곧게 떼고(옆으로 가지 않음, 떼는 중에 한 번 더 누르면 그 자리에서 멈춤) 연결을 연 채로 기다립니다. [▶ 이어서 그리기]를 누르면 멈춘 점 바로 위에서 종이 앞까지 빠르게, 같은 점까지 천천히 펜을 다시 대고 남은 명령을 그대로 이어 보냅니다(이미 그은 부분은 다시 긋지 않고, 획을 다 그은 뒤 멈췄으면 다음 획으로 바로 감). [⌂ 끝내기]를 누르면 끝냅니다. 저장된 대기 자세로 시작했고 "처음 위치로 되돌리기"를 켰으면 1번 대기 자세를 거쳐 호밍 자세(관절 0)로 돌아가고(돌아가는 중에 누르면 그 자리에서 멈춤), 아니면 펜을 뗀 그 자리에 둡니다. 일시정지는 몇 번이든 할 수 있고 횟수는 실행 기록(`pauses`)에 남습니다. 그리는 중이나 일시정지 중에 창을 닫으면 기다리지 않고 그 자리에서 끝냅니다(그리는 중이었으면 펜을 떼지 않음). 오류로 멈췄을 때는 위치를 믿을 수 없어 자동으로 움직이지도 이어 그리지도 않습니다.
  - **USB 포트 자동 연결:** 로봇 USB 케이블(WCH CH340/CH341/CH9102 칩)의 COM 포트를 자동으로 찾아 연결합니다. 케이블을 다른 USB 구멍에 꽂아 COM 번호가 바뀌어도 그대로 연결되고, 블루투스 직렬 포트 같은 다른 장치는 건너뜁니다. 설정 파일의 `port`에 COM 이름을 적으면 그 포트가 로봇 USB로 보일 때 먼저 씁니다. 로봇 USB 포트가 여러 개면 엉뚱한 장치를 리셋하지 않도록 고르지 않고 안내하므로 `port`에 COM 이름을 적어 주세요. CH340 계열이 아닌 어댑터는 `port`에 적으면 로봇 USB가 따로 없을 때 사용합니다.
  - **컨트롤러 방향 설정 확인:** 실물로 그릴 때는 호밍이 끝난 뒤, 첫 관절·접촉 이동 전에 `$$`를 읽어 방향 마스크 `$3`·`$23`이 설정의 `controller_settings_expected`(지금 123·60)와 같은지 봅니다. 다르거나 읽지 못하면 움직이지 않고 읽은 값을 보여 줍니다. 펌웨어 기본값(127·56)이면 보고 각도는 맞아 보여도 팔이 반대로 움직이기 때문입니다. 읽은 값은 실행 기록(`controller_settings`)에 남습니다. 2026-11-16부터 실물 그리기에서 이 확인을 거쳤고, 읽은 값(123·60)이 실행 기록에 남았습니다. 값이 맞는데 읽기만 실패하면 `controller_settings_expected`를 `null`로 두어 확인을 끌 수 있고, 끈 사실도 실행 기록에 남습니다.
  - GUI 상단에 감지한 포트(예: `USB: COM7 자동 감지`)와 컨트롤러 상태를 표시합니다. USB 표시는 장치 목록만 확인하고 포트를 열지 않습니다(포트를 열면 보드가 리셋됨). 컨트롤러 상태는 실제 그리기 연결에서 받은 응답으로 갱신합니다. 실제로 연결한 포트는 최종 확인 화면과 실행 기록(`port`)에 남습니다.
  - **카메라:** [로봇으로 그리기] 창 오른쪽에 카메라 실시간 보기가 있습니다. 위쪽 목록에서 노트북 내장 카메라 대신 외장 USB 카메라(예: Logitech BRIO)를 고를 수 있고, 새로 꽂았으면 [↻]로 목록을 다시 읽습니다. 고른 카메라는 장치 이름으로 저장해(`%APPDATA%\MirobotSketch\camera.json`) USB 구멍을 바꿔 번호가 달라져도 같은 카메라를 엽니다. 그 카메라가 빠져 있으면 "자동(처음 찾은 카메라)"으로 돌아갑니다. Windows에서는 DirectShow로 장치 이름을 읽고 같은 순서로 엽니다. 카메라를 끄거나 찾지 못해도 그리기는 진행됩니다. 웹캠이 연결되면 [준비 확인] 버튼이 나타납니다. 그림마다 종이 모서리에 X를 그려 두면, 그 버튼은 X 4개와 펜 끝이 보이는지만 기존 준비 안내에 얹어 보여 줍니다. 접촉 깊이는 확인하지 않고 종이 위치도 옮기지 않습니다. 카메라로 그리는 과정을 확인하는 설계 초안은 [docs/specs/2026-11-09-vision-guided-drawing.md](specs/2026-11-09-vision-guided-drawing.md)에 있습니다.
  - **종이 위치 맞추기:** 카메라 칸의 [종이 위치 맞추기]를 누르면 카메라 사진이 멈춘 창이 열립니다. 종이(판)의 왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래 귀퉁이를 차례로 누르고(찍은 점은 끌어서 고침), 종이 크기(기본 A4 가로 297×210 mm)를 확인한 뒤 저장합니다. 종이 중심은 호밍 직후 펜 끝 자리이므로 화면의 + 표시가 펜 끝과 맞는지 보면 됩니다. 저장한 뒤에는 미리보기에 계획한 그림(보라)·펜 범위(파랑)·공중 확인 범위(주황)가 실제 종이 위에 겹쳐 보이고, "계획한 그림 겹쳐 보기"로 끄고 켭니다. 그리기를 시작한 실행이 끝나면 카메라 사진과 겹친 사진을 나란히 `out/vision_*.png`에 남깁니다. 위치는 카메라마다 따로 저장하며(`%APPDATA%\MirobotSketch\vision_registration.json`), 카메라나 판을 옮기면 다시 찍어야 합니다. 로봇은 움직이지 않습니다. 인쇄할 수 있으면 `assets/aruco_markers_a4.pdf`의 표식으로 자동 맞추기를 할 예정입니다.
  - **모서리 표시에 맞춰 자동 조절:** 종이 네 귀퉁이에 붙여 펜이나 마커로 X 또는 십자를 그려 두면(표시 중심 = 귀퉁이), 그리기 창이 그리지 않는 동안 3초마다 카메라 사진에서 찾습니다("모서리 표시(X·십자)로 종이 위치 확인", 기본 켬). 같은 자리에서 세 번 연달아 보여야 씁니다. 저장된 종이 위치(로봇이 그리는 자리 기준)는 덮어쓰지 않고, 표시로 잰 실제 종이의 자리·회전·크기에 맞춰 로봇이 그릴 좌표를 옮깁니다("표시에 맞춰 그림 위치·크기 자동 조절", 기본 켬). 그림은 종이 중심으로 옮기고 종이와 같이 돌리며, 종이 크기에 비례해 키우거나 줄입니다(가로·세로 중 작은 쪽 비율, 그림 비율 유지). 크기는 잰 종이가 설정한 종이나 A3·A4·A5·B5·Letter와 3% 안으로 맞을 때만 바꾸고, 맞지 않으면 자리·회전만 맞춘 채 저장된 종이 위치가 틀렸을 수 있다고 알립니다. 옮긴 그림이 펜이 닿는 범위를 벗어나면 종이 중심 기준으로 들어갈 만큼 줄이고(최소 0.3배), 그래도 안 되면 원래 위치로 그리며 이유를 띄웁니다. 시뮬레이션·범위 검사·카메라 겹침·실제 전송은 맞춘 좌표를 쓰고, 편집·에이전트·종이 미리보기는 종이 좌표 그대로입니다. 실행 기록에 쓴 맞춤값(`paper_fit`)이 남습니다. 표시가 세 번 연달아 안 보이거나 자동 조절을 끄면 원래 위치로 돌아갑니다. 저장된 종이 위치가 아직 없을 때만 표시로 종이 위치를 만들며, 이때는 종이 중심이 호밍 직후 펜 끝 자리에 있다고 봅니다. [종이 위치 맞추기] 창도 표시가 보이면 네 귀퉁이를 자동으로 채웁니다. 표시는 흰 종이 위에 있어야 하고, 그리는 중에는 팔이 가려서 보지 않습니다.
  - **카메라 해상도 고정:** `camera.json`의 촬영 설정(예: 3840×2160) 사진이 나올 때까지는 화면에 보여 주지 않고, 끝내 다른 해상도로 열리면 이유를 띄웁니다. BRIO는 640×480으로 열리면 4K 화면의 가운데만 보여 1.33배 확대된 것처럼 보이고, 그러면 종이 위치가 맞지 않습니다. 종이 위치에는 찍은 사진 크기를 함께 저장하고, 화면 비율이 다른 사진에는 쓰지 않습니다.
  - **그리면서 선 확인:** 종이 위치를 맞춘 카메라로 그리는 동안 8초마다 다 그린 획에 선이 생겼는지 잽니다. 미리보기에서 선이 보인 획은 초록, 안 보인 획은 빨강, 아직 안 잰 획은 보라로 바뀌고, 카메라 칸 아래에 "보임 · 안 보임 · 가려짐(팔·홀더에 가림)" 개수가 나옵니다. 끝나면 한 번 더 재서 안내에 요약을 붙입니다. 로봇을 멈추지 않고, 아래 끝점 세로 줄 자동 보정만 아직 보내지 않은 획의 접촉점을 바꾸며, 가상 시뮬레이션에서는 재지 않습니다. 펜 선이 연해서 4K로 찍어야 잘 잡힙니다. 장치별 촬영 설정은 `camera.json`의 `"capture": {"Logitech BRIO": {"width": 3840, "height": 2160, "focus": 15}}`처럼 적습니다(초점은 카메라와 판 거리가 고정일 때만). 재기 전에 다 그린 획을 옮겨(±20 mm) 보며 실제 선에 가장 잘 맞는 자리를 찾습니다. 다 그린 획이 30개 이상이면 돌리고(±3°) 키워(0.92~1.08배)도 봅니다. 이건 이동만 맞춘 것보다 겹침이 3%p 넘게 늘 때만 씁니다(적은 획으로 잡음에 맞추지 않게). 종이를 다시 붙였거나 카메라가 틀어져도 맞게 잽니다. 2026-11-16 두 그림은 약 +7, −6 mm 어긋났고, 예전에는 선을 "안 보임"으로 재서 자동 보정이 끝점 물림을 잘못 줄였습니다. 11-18에는 카메라가 틀어져 +16, −12 mm·−2°·1.06배 어긋났는데, 예전처럼 ±10 mm 이동만 찾으면 겹침이 낮아 선 확인과 자동 보정이 아예 멈췄습니다(그 시험 종이 사진으로 다시 재면 겹침 98%, 48선 모두 보임, 약 2초). 맞춰도 선과 거의 안 겹치면 종이 위치를 다시 맞추라고 띄우고 자동 보정을 하지 않습니다.
  - **종이 위치 자동 보정(그린 선으로):** 실물로 다 그린 뒤 마지막 선 확인에서 계획과 실제 선이 확실히 맞으면(겹침 60% 이상, 획 30개 이상, 그림 둘레에서 0.5 mm 넘게 어긋남) 그때 찾은 변환(이동·회전·크기)으로 저장된 종이 위치를 고쳐 저장합니다. 지금 종이 위치의 원근은 그대로 두고 종이 위에서의 이동·회전·크기만 덧붙입니다. 덮어쓰기 전에 예전 파일을 `vision_registration_<시각>-backup_before_autoregister.json`으로 남기고 안내에 그 이름을 띄우므로, 잘못 고쳤으면 그 파일로 되돌리면 됩니다. 종이 위치는 종이 중심을 호밍 직후 펜 끝으로 보는데, 종이를 그 자리에 딱 맞춰 붙이지 않거나 카메라가 틀어지면 겹쳐 보기·선 확인이 어긋나기 때문입니다. 다음 그림부터 겹쳐 보기가 로봇이 실제로 그리는 자리와 맞습니다. 그래서 종이 위치는 처음 한 번(또는 카메라·판을 크게 옮겼을 때)만 [종이 위치 맞추기]나 모서리 표시로 잡으면 됩니다. 고친 뒤의 초록 종이 테두리는 실제 종이가 아니라 로봇이 종이 중심이라고 보는 자리 기준이라, 종이가 펜 중심에서 벗어나 붙어 있으면 그만큼 옆으로 보입니다. 2026-11-16에 이렇게 +7.3, −5.8 mm를 고쳤습니다. 11-18에는 시험 종이 48선으로 +16.2, −12.3 mm, 1.058배, −2.0°를 손으로 고쳤습니다.
  - **끝점 세로 줄 자동 보정:** 같은 선 확인에서 다 그린 획의 시작점·끝점마다 위아래로 뻗은 줄(펜을 세게 누른 채 내리거나 떼면 생기는 자국)을 잽니다. 미리보기에 주황 원으로 표시하고 "끝점 세로 줄: 시작 n/N · 끝 n/N"을 보여 줍니다. [끝점 세로 줄 자동 보정]을 켜 두면(기본) 지금 값으로 그린 끝점 8개 이상 중 20% 이상에 세로 줄이 있을 때 그쪽(시작/끝) 접촉점을 종이에서 0.2 mm 뒤로 물리고, 그리는 중이면 아직 보내지 않은 획부터 바로 씁니다. 물린 뒤 선이 안 보인 획이 앞 구간보다 15%p 넘게 늘면 0.2 mm 되돌립니다. 뗄 때 비스듬히(`edge_rise_mm`)가 켜져 있으면 끝점 줄은 뗄 때 값이, 시작점 줄은 펜 댈 때 값(`edge_land_mm`)이 맡고, **물림은 자동으로 움직이지 않습니다**(세로 줄로 올리지도, 선이 안 보인다고 줄이지도 않음). 같은 줄로 두 값이 한꺼번에 움직이면 고침이 겹치고(11-18 그림: 끝점 물림이 0.2 → 1.0으로 오르는 동안 비스듬히도 움직이다 엇갈려 멈춤), 2026-11-19에 접촉 누름을 1 mm 줄인 뒤로는 선이 옅어 '안 보임'이 실제보다 많이 잡히기 때문입니다(교수님 사진 109획에서 빠진 선이 없는데도 앞 40획의 54%가 '안 보임'으로 잡혀 시작점 물림이 0.4 → 0.2로 내려갔음). 범위는 0~1 mm이고 바뀐 값은 그림이 끝난 뒤 `drawing_config.json`의 `pen.start_backoff_mm`/`pen.end_backoff_mm`에 저장되어 다음 그림에도 씁니다. 카메라 사진만으로 판단하며 LLM·네트워크를 쓰지 않습니다.
  - **비스듬히 떼고 대기(`pen.edge_rise_mm`·`pen.edge_land_mm`):** 펜을 뗄 때 종이에 닿은 채 아래로 끌려 끝점마다 아래쪽 세로 줄이 생기면 씁니다. 종이에서 `edge_rise_depth_mm`(기본 1.5 mm) 떨어진 중간점을 뗄 때는 종이 위로 `edge_rise_mm`(0~3 mm), 내릴 때는 `edge_land_mm`만큼 옮겨(+는 종이 아래, −는 위, ±3 mm) 비스듬히 떼고 댑니다(둘 다 0이면 끔, 명령은 예전과 같음). 켜면 획마다 명령이 2개 늘고, 범위 검사는 옮긴 점까지 봅니다. 2026-11-16 그림(261획)을 카메라로 재 보니 1.8 mm 넘는 세로 줄이 대부분 아래쪽이었습니다(시작 아래 42/위 13, 끝 아래 40/위 19, 길이 중앙값 2.4 mm). **시험 종이(2026-11-16, `LOG/scripts/edge_rise_ladder/`):** 네 줄(y +40/+10/−25/−55 mm)에 5 mm 선 12개씩, 내릴 때·뗄 때 같은 값 0/1/2/3 mm를 섞어 긋고 휴대폰 사진으로 봤습니다. 끝점 줄은 0 mm에서 아래 약 2 mm, 1 mm에서 거의 없음, 2 mm에서 위 약 0.5 mm, 3 mm에서 위 약 1.5 mm였습니다. 시작점 아래 줄은 0 mm에서도 약 2.3 mm였고, 아래에서 올라오며 대면 1 mm마다 약 1 mm씩 길어졌습니다(일찍 닿아 그 길을 그대로 그림). 줄 높이에 따른 차이는 뚜렷하지 않았습니다. 펜이 닿아 짐이 걸리면 펜 끝이 약 2.3 mm 올라가는 것으로 보고(추정), 2026-11-18에 위에서 내려오며 대는 값 0/−1/−2/−3 mm를 같은 방식(`--knob land`)으로 그었습니다. 카메라 사진 6장 평균으로 보면 종이 왼쪽에서는 시작점 아래 줄이 4.2 → 3.5 → 1.3 → 1.2 mm로 줄었고, −3 mm에서는 위로 1.9 mm 뒤집혔습니다. 종이 오른쪽은 −3 mm에서도 3 mm가 남았고 끝점 아래 줄도 길어, 위치에 따른 다른 원인이 있는 것으로 봅니다(카메라 길이는 검증 안 된 값, 경향만). 저장소 설정 값은 자동 보정으로 그림마다 바뀌므로 `robot/drawing_config.json`의 `pen`을 보세요(11-19 기준 뗄 때 1.75, 댈 때 −0.75, 아래쪽 추가 0). **자동 조절:** [끝점 세로 줄 자동 보정]이 켜져 있고 `edge_rise_mm`가 0보다 크면, 선 확인이 끝점(펜을 뗀 자리)마다 줄이 종이 위·아래 어느 쪽으로 뻗었는지 재서(끝이 가로에 가까운 획만), 지금 값으로 그린 끝점 8개 이상 중 아래 줄이 10% 이상이고 위보다 5%p 넘게 많으면 0.5 mm 더(최대 3 mm), 위 줄이 그렇게 많으면 0.5 mm 덜(최소 0.5 mm) 합니다. `edge_land_mm`는 같은 방식으로 시작점(펜을 댄 자리)만 세어, 아래 줄이 많으면 0.5 mm 더 위에서(최대 −3 mm), 위 줄이 많으면 0.5 mm 덜(0까지) 내려오며 댑니다(`edge_rise_mm`가 0이면 바꾸지 않음: 명령 수가 바뀔 수 있음). 그리는 중이면 아직 보내지 않은 획부터 바로 쓰고, 설정 파일에는 그림이 끝난 뒤 한 번 저장합니다.
  - **종이 아래쪽은 더 비스듬히 떼기(`pen.edge_rise_low_mm`):** 끝점 높이가 y −20 mm보다 낮아질수록 이 값을 뗄 때 양에 더해 −60 mm 아래에서는 다 더합니다(합 최대 3 mm, 저장소 설정 0). 자동 보정이 아래쪽(y −40 mm 아래)과 위쪽(y −20 mm 위) 끝점의 아래·위 줄을 따로 세어, 아래쪽만 아래 줄이 10% 이상이고 위쪽보다 10%p 넘게 많으면 0.5 mm 더, 아래쪽만 위 줄이 그렇게 많으면 0.5 mm 덜 합니다. `edge_rise_mm` 자동 조절은 이 추가가 걸리지 않는 높이의 끝점만 봅니다.
  - **판단이 오가면 가운데 값으로 고정, 저장은 끝난 뒤 한 번:** 한 그림 안에서 어떤 값(시작·끝점 물림, 뗄 때·댈 때 비스듬히, 아래쪽 추가)이 바꾼 방향과 반대로 다시 바뀌려 하면, 앞뒤 판단이 그 사이를 가리키는 것으로 보고 지금 값과 새 값의 가운데로 둔 뒤 그 값은 그 그림에서 더 바꾸지 않습니다. 다른 값은 계속 고칩니다. 안내에 "판단이 오가서 가운데 값으로 고정: …"이 나옵니다. 예전에는 이럴 때 자동 보정을 통째로 멈췄습니다. 그러자 11-18 그림에서 댈 때 값이 −2 → −1.5 → −1로 간 뒤 −1.5로 돌아가려던 순간 멈춰, 나머지 획을 모두 −1로 그렸고 그 구간에 아래 줄이 많았습니다. 그리는 중에 바뀐 값은 남은 획에만 쓰고, 설정 파일에는 그림이 끝난 뒤 한 번만 저장합니다. 2026-11-16 22:41 그림에서는 선이 연해 "선이 안 보임"과 "세로 줄 있음" 규칙이 번갈아 걸렸습니다. 그래서 시작점 물림이 0~0.8 mm를 16번 오르내렸고, 끝 값이 저장돼 손으로 되돌려야 했습니다. 지금은 뗄 때 비스듬히가 켜져 있으면 물림이 세로 줄로 움직이지 않습니다.
  - **비스듬히 값은 끝점이 충분히 모이고 한쪽이 확실할 때만:** 뗄 때·댈 때 비스듬히와 아래쪽 추가는 위의 비율 조건에 더해, 지금 값으로 그린 끝점 중 위·아래를 가른 것이 30개 이상이고, 많은 쪽 줄이 반대쪽보다 반반이라고 보기 어려울 만큼(부호 검정 한쪽 p ≤ 0.05, 예: 21 대 10은 바꿈, 6 대 2는 안 바꿈) 많을 때만 바꿉니다(`pen_correction.DIR_MIN_ENDPOINTS`·`DIR_P`). 아래쪽 추가는 아래쪽·위쪽 끝점이 각각 30개 이상이어야 합니다. 2026-11-18 두 그림에서는 구간마다 끝점 10~24개(예: 아래 5·위 2)로 판단했습니다. 그래서 같은 댈 때 −1 mm를 15:53 그림에서는 "아래 줄", 20:44 그림에서는 "위 줄"로 보고 반대로 움직였습니다. 끝난 뒤 사진으로 다시 재면 두 그림의 시작점 세로 줄은 25%·24%로 같았습니다.
  - **실행 기록의 펜 값 변화와 시각:** 실행 기록(`runs/run-*.json`)의 `pen_changes`에 그리는 동안 쓴 값(시작·끝점 물림, 뗄 때·댈 때 비스듬히, 아래쪽 추가)과 그 값을 쓰기 시작한 획 번호·시각을 남깁니다. `config_snapshot`에는 끝났을 때 값만 있어서, 전에는 컨트롤러 기록(2만 줄에서 잘림)으로 되짚어야 했습니다. `started_local`은 시작 시각, `finished_local`은 끝난 시각입니다. 파일 이름은 예전처럼 끝난 시각입니다.
  - **남은 시간:** 진행 줄의 남은 시간은 처음 1분 동안 미리 잰 예상 시간을 보여 주고, 그 뒤로 지금까지 걸린 시간 비율로 고칩니다. 예전에는 첫 명령 직후 0.3초 남짓으로 비율을 재서, 22:41 그림(실제 74분)을 시작할 때 "남은 시간 약 34분"으로 보였습니다. 미리 재는 예상 시간에서는 명령마다 0.1초 지연을 더하던 것을 뺐습니다(`timing.assumed_command_latency_s` 0). 그리기 명령은 응답만 받고 이어 보내 이동과 겹치기 때문입니다. 10월 29일 이후 실물 완료 기록 17개에서 실제 시간은 이동 이론값의 0.77~0.92배였으므로, 지연을 빼도 예상은 아직 실제보다 8~30% 깁니다. 예상이 약 12% 짧아져 [자동 세팅](목표 45분)은 예전보다 획이 조금 더 많은 설정을 고를 수 있습니다. 짧은 획이 늘면 시작점 세로 줄도 늘어나니, 예전과 비슷한 그림을 원하면 목표를 40분쯤으로 잡으세요.
  - **J1 방향 보정(실험, 기본 끔):** 베이스(J1)에 유격이 있어 같은 자리라도 왼쪽에서 왔는지 오른쪽에서 왔는지에 따라 선이 옆으로 1~3 mm 어긋납니다. `drawing_config.json`의 `pen.j1_direction_offset_deg`(늘어나며 도착한 각 − 줄어들며 도착한 각, ±3° 안)를 넣으면, 실행기가 목표점마다 도착 방향의 반대쪽으로 절반씩 돌려 보냅니다. 방향이 바뀌는 점에서는 같은 점으로 한 번 더 보내 유격을 먼저 메웁니다(`j1-takeup`). 펜을 내리고 올리는 이동은 J1이 돌지 않게 베이스에서 뻗는 선 위로 하고, 획마다 첫 그리기 방향으로 공중에서 미리 돌립니다(`j1-approach`). 0이면 명령은 예전과 같습니다. 값은 실물 시험으로 정해야 하며, 공중에서 잰 값과 펜을 댄 채 잰 값의 부호가 달랐습니다.
  - **크게 보기:** 카메라 칸의 [크게 보기]는 따로 창을 엽니다. "그림 부분"은 그림 둘레를 카메라 원본 해상도로 잘라 보여 주고, "종이 전체"·"사진 전체"로 바꿀 수 있습니다. 창 크기에 맞춰 커지며, 두 번 누르면 화면 가득 봅니다. "계획 겹쳐 보기"를 끄면 펜 선만 봅니다.
  - **카메라 화면 공유:** 카메라는 한 프로그램만 열 수 있어서, 그리기 창이 카메라를 켜고 있는 동안 `out/camera_live/`에 2초마다 `view.jpg`(그림 부분 + 계획 겹침), `raw.jpg`(그림 부분 원본), 10초마다 `full.jpg`(사진 전체)와 `status.json`(진행·선 확인 문구)을 씁니다. 터미널이나 다른 도구는 카메라를 열지 않고 이 파일을 읽어 지금 종이를 봅니다.
  - "종이·펜·주변 확인" 체크를 해야 시작할 수 있고, 공중 모드가 기본입니다.
  - 종이나 펜 위치를 바꿨다면 "종이·펜 위치 변경: 다시 보정"을 선택하세요. 선택하지 않으면 보정 없이 설정에 저장된 값(`plane_compensation`, `limits`)으로 바로 호밍 → 그리기를 진행합니다. 종이 보정이 안 된 상태로 실물 연결하면 최종 확인 화면에 "종이 보정 없음"이 표시됩니다.
  - 앱은 전송에 사용한 종이 좌표를 `out/run_strokes_*.json`에 저장하고 `LOG/runs/`의 실행 기록에서 해당 파일을 가리킵니다. 실물 펜다운은 보정으로 접촉을 확인한 영역 안에서만 시작할 수 있습니다. 넓은 범위 옵션은 그 밖의 공중 경로 확인에 사용할 수 있습니다.
  - **가상 시뮬레이션**(로봇 없이, 1~500배속)으로 같은 흐름을 시험할 수 있습니다. 명령줄에서는 `mirobot draw <json> --execute --virtual`입니다.
  - WSL2 + ROS 2가 있는 PC에서는 그리는 동안 **RViz가 로봇 진행(명령 응답)을 실시간으로 따라갑니다**.

#### 명령줄과 SVG

```bash
mirobot-strokes photo.jpg --type photo --out out/photo
```

- `--type photo|illustration|manga` : 이미지 종류별 추천 설정 (`mirobot_sketch/presets.py`)
- `--detail low|medium|high` : 상세도. 낮출수록 획 수와 그리는 시간이 줄어듭니다.
- `--rembg` / `--no-rembg` : 배경 제거 (결과는 `out/cache/`에 저장해 재사용)
- `--median 11` : 만화 스크린톤(망점)처럼 작은 무늬를 지웁니다.
- `--dedupe 4` : 펜 굵기보다 가까운 이중선(굵은 선의 양쪽 경계)을 하나로 (기본 4px, 0=끔)
- `--merge 4` : 끝점이 만나는 획을 이어 그려 펜 올림 횟수를 줄입니다 (기본 4px, 0=끔)
- `--lines dark` : 깨끗한 선화에서 어두운 선의 중심선을 그립니다.
- `--box W H` : 그리기 상자 크기(mm). 기본값은 100 × 100입니다.
- `--svg` : 펜 플로터·GRBL 장비용 SVG(`out/photo.svg`)도 저장합니다. 아래 [다른 장비에서 쓰기](#다른-장비에서-쓰기-svg)를 보세요.

`out/photo.json`과 비교 이미지 `out/photo_preview.png`(입력 / 선 후보 / 획 / 그리는 순서)가 만들어집니다.

#### 다른 장비에서 쓰기 (SVG)

획 JSON은 종이 중심 기준 mm 좌표라 로봇과 무관합니다. 선 추출 결과를 AxiDraw 같은 펜 플로터나 GRBL 기반 장비에서 쓰려면 SVG로 내보냅니다.

```bash
mirobot-strokes photo.jpg --type photo --out out/photo --svg   # 사진에서 바로
mirobot-svg out/photo.json                                      # 이미 만든 JSON(GUI에서 저장한 파일 포함) -> out/photo.svg
```

- 문서 크기는 실제 종이 크기(A4 가로 297 × 210mm)이고, SVG 한 단위가 1mm입니다. 그림은 JSON과 같은 자리(종이 중심)에 놓입니다.
- 획 하나가 `<path>` 하나이고, 그리는 순서를 그대로 둡니다.
- AxiDraw(Inkscape 확장·`axicli`), [vpype](https://github.com/abey79/vpype), SVG → G-code 변환기처럼 SVG를 읽는 도구에 넘길 수 있습니다. vpype로 다시 읽어 종이 크기·위치·획 수가 JSON과 같은지 확인했고, AxiDraw·GRBL 실물 장비에서는 확인하지 않았습니다.

### 2. 획 JSON → 로봇

```bash
mirobot-draw out/photo.json
```

기본은 **dry-run**이라 로봇을 움직이지 않고 G-code 파일과 요약만 만듭니다. 실제로 그리기 전에 다음을 준비합니다.

1. 전원을 켜고 중앙 버튼을 2초 눌러 호밍한 뒤 Idle 상태를 확인합니다.
2. 펜 끝을 종이 중앙에 둡니다.
3. `robot/drawing_config.json`의 중심 TCP, 부호를 확인합니다. 포트는 자동으로 찾습니다(`port`가 `auto`이거나 적힌 COM 포트가 없을 때).

준비가 끝나면 실행합니다.

```bash
mirobot-draw out/photo.json --execute
```

실행 결과는 `LOG/runs/`에 저장됩니다. 처음 실행할 때는 `trajectories/orientation-test-F.json`으로 좌우·상하 방향부터 확인하세요.

- `--air` : 펜을 종이에 대지 않고 같은 경로를 따라갑니다(도달 범위·충돌 확인용).
- `--pending-limits` : 실물 확인 전의 넓은 범위(도달 지도에 맞춘 지붕 모양, 좌우 ±125 · 아래 −85 · 위 +42.5~+57.5mm)로 검사합니다. 범위 확인 시험(`trajectories/border-test-wide.json`)과 큰 그림에 씁니다.

**더 크게 그리기:** GUI의 "그리기 크기"를 최대 250mm까지 올릴 수 있습니다. 이 값은 가로·세로 상자의 한 변이며 사진 비율은 유지됩니다. 예를 들어 가로 사진을 120mm로 설정하면 실제 그림은 120×71mm 정도입니다. 넓은 범위에 들어가도록 큰 그림은 조금 아래로 옮기고, 세로로 긴 그림은 위쪽 한계에 맞춰 줄입니다. 넓은 범위는 로봇의 공중 이동과 시뮬레이션을 확인하는 데 쓰며, 펜으로 그리려면 해당 그림 전체의 접촉 범위를 실측 보정해야 합니다. 실물 확인 절차는 `robot/drawing_config.json`의 `_limits_pending_note`와 [LOG](../LOG/2026-09-26-bigger-drawing.md)를 따릅니다.

#### 종이 평면·실물 그리기 범위 보정(캘리브레이션)

종이와 벽 사이 간격은 사람이 맞춘 뒤, 중심과 사각형 네 모서리의 접촉 좌표로 앞뒤(X) 편차와 평면 기울기를 계산합니다. 로봇에는 접촉 센서가 없으므로 펜 끝 접촉은 사람이 눈으로 확인합니다. 웹캠 없이 실행할 수 있습니다. 보정은 자동으로 시작하지 않습니다. GUI의 "다시 보정" 선택 또는 `mirobot-draw --execute --calibrate`로 요청했을 때만 그리기 전에 안내합니다. 보정 없이 그릴 때도 종이 허용 범위(`limits`) 검사, 시작 위치 검사, 사람의 최종 확인은 그대로 적용되므로 `limits` 밖의 그림은 펜으로 그릴 수 없고 공중 모드만 됩니다. 가상 시뮬레이션은 보정 절차를 건너뜁니다.

GUI에서 확장 범위의 그림을 선택하면, 앱은 그림 좌표의 외곽에 1 mm 여유를 더한 직사각형을 펜업으로 따라가며 모서리마다 확인을 받습니다. 이후 네 모서리의 접촉을 직접 확인해 그 그림에 필요한 가로·세로 영역을 보정합니다. 예를 들어 120×71 mm 사진은 대략 122×74 mm 영역을 확인합니다. 접촉이 확인되지 않으면 실물 펜다운은 시작하지 않습니다.

위쪽 도달 한계(종이 중심 위 +55~57.5 mm) 때문에 큰 그림은 종이 중심보다 아래로 배치됩니다. 120×120 mm 그림은 세로가 −65 ~ +55 mm 범위이고, 보정도 이 범위(종이 중심 기준, 좌우 대칭)의 네 모서리를 측정합니다. 이 영역이 통과하면 실행 한계가 그 직사각형(`x_max_mm`, `y_min_mm`, 평평한 위쪽 한계)으로 저장됩니다. 정사각형은 이론상 약 138 mm까지 로봇 도달 범위 안에 들어옵니다(시뮬레이션 PASS). 다만 측정한 평면 잔차가 1 mm를 넘으면(종이가 휘었거나 벽과 벌어진 경우) 설정을 바꾸지 않으므로 종이를 평평하게 고정하고 다시 측정해야 합니다.

```bash
python -m mirobot_sketch.calibration             # 예상 탐색 범위만 표시
python -m mirobot_sketch.calibration --execute    # 실물 보정
# 패키지를 다시 설치하면 mirobot-calibrate [--execute] 명령도 사용할 수 있습니다.
```

전원과 USB를 연결하고 실행하면 시리얼 연결이 한 번 열립니다(컨트롤러가 재시작됨). 중앙 버튼으로 호밍한 뒤 종이 중심과 간격을 맞추고 고정하세요. 펜업으로 60×60 mm 사각형부터 시작해 한 변을 10 mm씩 늘립니다. 각 모서리에서 간섭이 없는지 확인하고 `Enter`로 계속합니다. `c`는 현재 완성한 크기(확장 중에는 직전 안전 크기)를 선택하고, `q`는 취소합니다. 선택한 사각형의 네 모서리에서는 `+`/`-`로 X축을 0.25 mm씩 조정합니다. 예를 들어 `++++++++`는 2 mm 벽 쪽 이동입니다. 펜 끝이 막 닿았을 때 `Enter`로 기록하고, 종이에 눌러 자국을 내지 마세요.

다섯 접촉점으로 계산한 최대 평면 잔차가 1 mm 이하여야 설정을 갱신합니다. 통과하면 중심 TCP, 평면 보정값, 확인된 정사각형 한계가 `robot/drawing_config.json`에 저장되고 전체 측정값은 `LOG/calibrations/`에 남습니다. 편차가 크거나 사용자가 중단하면 기존 설정을 유지합니다. 로봇 포트나 설치 위치가 바뀌면 다시 보정하세요.
